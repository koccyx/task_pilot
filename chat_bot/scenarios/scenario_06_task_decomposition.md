# Сценарий: Декомпозиция сложной задачи

**Триггер**: "разбей задачу", "декомпозируй задачу", "создай подзадачи", "разложи на подзадачи"

**Когда использовать**:
- Пользователь просит разложить большую задачу на несколько исполнимых подзадач.
- Пользователь описывает сложную инициативу и хочет сразу получить набор рабочих карточек.

**Шаги (выполняются последовательно в одном ответе)**:
1. Определить доску.
   Если доска не указана и не восстанавливается из контекста, задать один короткий уточняющий вопрос.
2. Определить источник декомпозиции:
   - если пользователь ссылается на существующую карточку, сначала получить её через `manage_cards(action="get", card_id=...)`;
   - если пользователь дал только текст задачи, использовать сам текст сообщения как исходное описание.
3. На основе названия и описания самостоятельно составить 3-7 конкретных подзадач.
   Требования:
   - подзадачи должны быть исполнимыми и проверяемыми;
   - не использовать общие пункты вроде "Implementation" или "Testing", если можно назвать конкретный результат;
   - если пользователь просит "на меня", использовать имя из пользовательского профиля.
4. Для каждой подзадачи последовательно вызвать:
   - `manage_cards(action="create", board="..." или board_id=..., title="...", description="...")`
   - при необходимости `manage_members(action="set_responsible", card_id=..., owner_name="...")`
5. В финале дать короткий отчёт:
   - сколько подзадач создано;
   - на какой доске;
   - список созданных карточек с ID.

**Важно**:
- Не просить подтверждение на каждый шаг.
- Если исходная задача слишком размытая, сначала уточнить недостающий контекст, а не создавать шаблонные карточки.
- Если есть существующая родительская карточка, можно явно указать в описании подзадач, что они относятся к ней.
